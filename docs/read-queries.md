# Read saved expenses and appointments

The signed, owner-only history application can answer stored-data questions using the existing configured workbook and secondary Calendar. These queries use the current read permissions; no new scopes or credentials are needed. They do not append expenses, create events, change a draft or create a confirmation nonce. Conversation receipts and the existing usage ledger continue normally.

This source revision replaces the semantic keyword pre-router with model-selected `query_expenses` and `query_calendar` tools. The model sees raw recent dialogue, the authoritative Bangkok timestamp, exact catalog labels and the latest verified delivered query scope. It interprets language, aliases, typos, follow-ups and new intent; code validates typed arguments and performs fixed-resource reads and arithmetic. A source push does not deploy this change.

Examples:

- `สรุปรายจ่ายเดือนนี้` — total saved expenses for the current Bangkok month.
- `ค่าอาหารวันนี้เท่าไหร่` or `สรุปรายจ่ายเดือนนี้หมวดอาหาร` — resolve an existing catalog category; ask if the label is unknown or ambiguous.
- `ดูรายการรายจ่ายตั้งแต่วันที่ 2026-11-01 ถึงวันที่ 2026-11-07` — total and saved entries for an inclusive range.
- `เฉพาะหมวดย่อยเครื่องดื่ม`, `แยกรายการให้หน่อย`, `แล้วเดือนก่อนล่ะ` — continue the latest delivered query when that catalog label exists.
- `ดูนัดพรุ่งนี้`, `สัปดาห์หน้ามีนัดอะไรบ้าง`, `ดูนัดถัดไป` — list saved timed/all-day occurrences in the configured Calendar.
- `แล้วเมื่อวานล่ะ` — continue the latest delivered query. An unrelated response, failed delivery, different workbook or expired receipt does not supply query context.

A new explicit expense question starts with all items unless it supplies a filter. Date-only follow-ups retain the preceding filter; `ทั้งหมด` clears it. Calendar title/type filters are passed explicitly as `filter_text` so the server can decline an unsupported filter instead of silently returning all events.

The model resolves wording and typos to exact existing item/category/subcategory labels supplied by the catalog; an unknown or ambiguous label requires clarification. No competing semantic parser chooses filters. Category totals use the current Database mapping, not a reconstructed historical category. Missing or ambiguous stored-item mappings prevent a category total from being presented as complete.

Dates use Asia/Bangkok. Weeks run Monday–Sunday; relative dates are anchored to the current owner message timestamp. The model interprets Thai month names and abbreviations, Buddhist years, ISO dates and day/month/year dates into typed calendar frames or explicit inclusive dates. Relative week/month/year offsets are selected by the model and expanded using calendar arithmetic on the authoritative Bangkok date. New periods carry a literal owner `period_text` citation; the current clock alone cannot fill an omitted period. For filter/view-only follow-ups, `date_mode=previous` explicitly selects dates from the latest verified query receipt; it cannot invent a default when that receipt is absent. An unqualified month uses its first through last day; an explicit “จนถึงวันนี้” clips the end to today. Missing or conflicting periods require clarification. Expense queries retain the existing limit of 367 inclusive dates. Calendar queries cover at most seven dates; The model-selected `upcoming` mode for “นัดถัดไป” covers the current time through the next six dates and includes events still in progress. Queries do not search other calendars or filter event titles/types.

Expense totals use Decimal arithmetic over a complete bounded input read. Sheets identity, headers and configured grid bounds must pass. Malformed values, incomplete mappings, access failures or an oversized grid yield an unavailable response rather than a zero balance. Income has no verified storage mapping: it is unsupported, not zero, and a remaining balance cannot be computed.

Calendar reads include transparent events and omit cancelled events. Timed events display Bangkok times; all-day exclusive end dates display the correct inclusive last day, including externally saved multi-day events. Pagination is limited to three pages of 20 events; an unfinished or inconsistent result is reported unavailable. Successful replies show at most 20 entries/events and disclose when more exist. Long labels are shortened for display. A complete empty read can report zero saved records; it does not establish availability on other calendars.

The optional reply phase composes natural Thai by selecting phrases around separate immutable period, filter, total and count slots. Verified row details are appended by the server; the model need not repeat or enumerate them. Amounts/counts include their units, preventing unit swaps; required schema fields retain every header fact exactly once, and per-slot phrase enums cannot invent dates, quantities, names, success or change units. A model failure returns a natural server fallback. Distinct non-sensitive reason codes distinguish invalid arguments, unknown filters, incomplete mappings, schema errors, provider failures and unfinished reads. They do not establish the cause of any earlier live incident. A terse dated title such as `พรุ่งนี้ Workshop` asks whether to add an appointment or view saved events, and creates no draft. This also applies after a previous query.

Run the offline regression suite and `python scripts/check_ci.py` as described in [development](development.md). Offline tests inject explicit model tool choices; they do not demonstrate real language understanding. The synthetic inference corpus in `tests/fixtures/query_inference.json` defines paraphrase, follow-up, fault, injection and write-regression scenarios for a separately authorized paid runner; private credentials, responses, cost receipts and approvals stay outside the checkout. Provider tests cover inclusive boundaries, midnight/leap-year dates, totals/listing, filters, all-day events, pagination, incomplete reads, cold restore/replay and confirmation isolation. A source push or passing CI does not deploy this feature.
