# Role benchmark protocol

Version `v1` evaluates only the explicitly authorized GPT-6 Luna baseline for query planning, response style, critic review and composed expense/Calendar turns. Configurable role maps and prices are in `v1/config.json`; the reusable `scripts/benchmark_driver.py` accepts an authorized transport callback and never discovers credentials or silently tries alternative models. Production remains pinned to its reviewed model and two-call policy.

`v1/development` contains cases already used to investigate failures and tune behavior. `v1/evaluation` uses new synthetic records, dates, names, amounts and utterances. Freeze the labels, prompts, runtime archive, runner and config hashes in `v1/freeze.json` **before** evaluation. Never tune against a held-out failure and then reuse that split as fresh evaluation: move it to development and create a new held-out version. Preserve initial failures, independent repetitions and manual reruns; do not report only the best run.

Each repetition starts fresh synthetic state. Both speakers and trusted query receipts persist across turns and cold factories. Query labels define the tool/domain, normalized interval/filter/view and numerical result. Write labels define exact provider effect names, amounts, dates and event boundaries after review and explicit confirmation. All Google, LINE and state calls are mocked; only the authorized role-model request is real. Public `tests` provide the signed factory fixtures. Private adapters bind existing credentials and retain operational responses/usage outside this repository; their hashes are recorded for the workspace owner.

Report per-role and composed metrics with both unique-scenario and attempt counts:

- Planner: tool selection, typed argument acceptance, normalized date/filter accuracy and end-to-end semantic success. Code's calendar arithmetic is part of the composed result, not model arithmetic.
- Style: exact grounding/completeness of delivered text, actual LLM realization versus trusted fallback, length/conciseness proxies and a human-review sample. Do not substitute the critic or the generating model's own rating for human naturalness judgments; leave human scores pending when no human rated them.
- Critic: false accept/reject by severity, precision, recall, valid-output rate, timeout/fallback rates and latency. Standalone adversarial text is injected after rendering to test critic sensitivity. Its literal-span comparison is a development baseline, **not** a claim that corrupt text passed the stricter production slot renderer.
- Cost: input/output/cache-read/cache-write tokens, received usage estimates, unknown-request holds, retry rate, latency p50/p95 and cost per successful answer. Estimates are not invoices. Record baseline two-call timing and the explicit development-only third critic call separately.

Thresholds are predefined in `v1/config.json`. In particular, any observed critical action-status false accept blocks enabling the critic as a production gate. A same-model critic can repeat the writer's errors; even zero observed errors has finite-sample uncertainty. Wilson intervals are descriptive per attempt because repetitions within a scenario are correlated. Also report macro results by unique scenario and avoid universal accuracy claims.

The bounded prototype in `scripts/response_critic.py` runs once after exact validation, accepts only strict pass/fail/reason JSON and falls back to trusted rendering on rejection, invalid output, API failure or its two-second deadline. There is no regeneration loop. Its third-call allowance exists only in the development runner. Production integration would require a separate flag, guarded reservation/transport contract, a three-call budget, LINE-deadline assessment and receipt/confirmation binding review before release. No such production configuration is enabled by this benchmark.

The v1 labels were predefined synthetic oracle fixtures prepared by Codex, with no independent human adjudication claimed. The frozen helper's comment describing them as human-authored is imprecise; the result summary states their actual provenance. Human style ratings remain a separate pending step.
